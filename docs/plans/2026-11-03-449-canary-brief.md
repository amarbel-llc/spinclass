# Guarded-gate canary (spinclass#449): operator brief

Status: ready, 2026-11-03, spinclass/light-cedar. Runs only after the
spinclass binary at origin/master 5cfd5adc2943 (or later) is deployed on
flic, and only with the operator's explicit exception to the "confined only
for research-only work" rule, since the canary is a confined worker that
commits. The coordinator (circus/eager-holly) asks for both.

Standing rules: every merge in the canary lands with no post-merge target;
the operator reads every `flake.nix` and `flake.lock` input change before
any `sc merge` of the canary branch; nothing in this brief is run by
light-cedar itself (the coordinator said: prepare, do not spawn).

## Run in this order

1. After the deploy: `sc version` shows 5cfd5adc2943 or later (step 1).
2. Create the repo: the 12-line block under "Repo" below, copied as one
   paste into a terminal in `$HOME/eng/repos`.
3. Step 1 preflight (`sc validate`, the inputs-eval recipe).
4. Step 2 spawn, only when the coordinator says go.
5. Step 3 positive check, step 4 probes, step 5 landing, step 6 optional.

## What is being proven

A session launched confined gets the guarded gate on merge and check
(FDR 0035, `[hooks].confined-pre-merge`, default
`nix flake check --no-update-lock-file`): no repair, no direnv, a scrubbed
environment, the lock policy before the command (allow-list of reference
kinds, every declared input matched against the lock node's original,
nested overrides and follows included, the inputs read by a restricted
`nix eval` on stdin inside a memory-bounded systemd scope), and a refusal
that names only node names, input paths and reference kinds. Plus the
#455 half: a confined caller's rebase in progress owns nothing.

Two facts shape the steps. `check-this-session` and `merge-this-session`
are gated off for a confined caller (serve_caller_gate), so the gate is
driven by the OPERATOR with `sc check` and `sc merge --target`, not by the
worker. And the gate refuses a frontend whose own direnv points into a
worktree (`DIRENV_DIR`, `DIRENV_FILE`), so the operator's shell must have
no worktree `.envrc` loaded when it runs them.

## Repo: a fresh throwaway, not sc-smoke-ab (recommendation)

sc-smoke-ab has no flake and sets `[hooks] disable-merge = true`, so it
cannot exercise the gate or the landing without changes that would also
change what it smokes. A throwaway repo with a flake that has NO inputs and
a root-only lock needs no network for the positive path; the negative probes
add inputs. Suggested name `sc-canary-449` beside the other repos
(`$HOME/eng/repos/`), with a bare `origin` so the landing has something to
push to (merges read the remote tracking ref and push origin, #126/#315).

```sh
cd "$HOME/eng/repos"
git init --bare sc-canary-449.git
git init -b master sc-canary-449 && cd sc-canary-449
cat > flake.nix <<'EOF'
{
  outputs = { self }: {
    checks.x86_64-linux.smoke = derivation {
      name = "smoke"; system = "x86_64-linux";
      builder = "/bin/sh"; args = [ "-c" "echo ok > $out" ];
    };
  };
}
EOF
nix flake lock            # writes a root-only lock; no fetch
printf 'canary for spinclass#449\n' > README.md
git add -A && git commit -m "init: a flake with no inputs"
git remote add origin "$HOME/eng/repos/sc-canary-449.git"
git push -u origin master
```

No repo-level sweatfile is needed: the guarded gate reads
`[hooks].confined-pre-merge` from the trusted layers only (default when
unset) and ignores a repo-level value with a recorded point. `[confinement]
enabled` must already be on in a trusted layer (it is wherever confined
spawns run today). Check with `sc validate` from inside the repo.

## Step 1: preflight on the deployed host

```sh
sc version                      # must show 5cfd5adc2943 or later
cd "$HOME/eng/repos/sc-canary-449" && sc validate
cd "$HOME/eng/repos/spinclass" && just explore-guarded-gate-inputs-eval
```

The last command is the real-nix smoke of the evaluation the gate runs:
`restrict-stdin honest` must print `["a","b"]`, the `scoped` probe must
print the canonical JSON with `exit=0`, the hostile shapes must all be
`exit=1` with `marker-in-output=no`, and `canon-lockshape` must agree with
the `original` lines above it. It takes about a minute and touches only a
temp dir and the nix store (dummy marker only).

## Step 2: spawn the confined canary

From a terminal inside `sc-canary-449` (any directory in the main checkout;
`sc spawn` with no `--repo` spawns in the current repo):

```sh
sc spawn --confined --profile canary-spinclass \
  --description "449 guarded-gate canary" \
  --brief 'You are a confined canary for the spinclass guarded merge gate. Do exactly this and nothing else: append the line "canary: guarded gate round 1" to README.md with the Edit tool; if a grit_commit tool is available, commit it with the message "canary: round 1", otherwise say so. Then send one chat message to the session key the operator gives you below with: the tools you have (name them), whether you committed, and the HEAD commit if you know it. Do not merge, do not run recipes, do not create files. Operator session key: <OPERATOR-SESSION-KEY>'
```

Record the printed `session_key` (`sc-canary-449/<branch>`) and
`worktree_path`. If the profile has no grit tools, commit for it from
outside the unit:

```sh
git -C <worktree_path> add -A && git -C <worktree_path> commit -m "canary: round 1"
```

The gate judges the committed tree, whoever committed it.

## Step 3: the guarded check (positive)

From a shell with NO worktree direnv loaded. Either run from your home
directory, or unload direnv for the command:

```sh
cd <worktree_path>
direnv exec / sc check --format plain
# fallback if direnv exec is unavailable in that shell:
# env -u DIRENV_DIR -u DIRENV_FILE -u DIRENV_DIFF -u DIRENV_WATCHES sc check --format plain
```

Expected in the record: a point
`guarded gate <branch>: `nix flake check --no-update-lock-file` (from <layer or default>), in the build worktree ...`;
no repair point; no `direnv exec` anywhere in the output; the smoke check
built in the nix sandbox; exit 0. While it runs, in a second terminal:

```sh
systemctl --user list-units 'ringmaster-*' --no-pager
```

shows a transient `ringmaster-<id>-inputs.scope` for the inputs evaluation
(short-lived; `journalctl --user -o cat -u 'ringmaster-*-inputs.scope' --since -10min`
afterwards). The refusal cost to confirm: if the scope tier is unavailable
the check fails before the command with "the inputs evaluation runs only
inside a scope".

## Step 4: negative probes (each: commit, check, read the refusal, reset)

All in `<worktree_path>`, from outside the unit, with `sc check` run as in
step 3. Before the first probe and after the last, snapshot the store so a
leak would show:

```sh
ls /nix/store | sort > /tmp/canary-store-before
# ... probes ...
ls /nix/store | sort > /tmp/canary-store-after
comm -13 /tmp/canary-store-before /tmp/canary-store-after   # inspect anything new; the marker below must not appear
```

Use a dummy marker directory, never a real path:
`mkdir -p /tmp/canary-outside && echo CANARY-DUMMY-MARKER-$RANDOM > /tmp/canary-outside/marker.txt`.

(a) An input the lock lacks:

```sh
cat > flake.nix <<'EOF'
{
  inputs.leak = { url = "path:/tmp/canary-outside"; flake = false; };
  outputs = { self, leak }: {
    checks.x86_64-linux.smoke = derivation {
      name = "smoke"; system = "x86_64-linux";
      builder = "/bin/sh"; args = [ "-c" "echo ${leak} > $out" ];
    };
  };
}
EOF
git commit -am "probe a: declared input the lock lacks"
```

Expected: refused before the command; the reason contains
`leak: missing from the lock` and nothing else about the input (no path,
no hash). Then `git reset --hard HEAD~1`.

(b) The same name locked as a remote node (the F1'' shape): keep probe (a)'s
`flake.nix`, and write a lock whose `leak` node is a github reference:

```sh
cat > flake.lock <<'EOF'
{"nodes":{"leak":{"flake":false,"locked":{"lastModified":1,"narHash":"sha256-x","owner":"NixOS","repo":"nix","rev":"0000000000000000000000000000000000000000","type":"github"},"original":{"owner":"NixOS","repo":"nix","type":"github"}},"root":{"inputs":{"leak":"leak"}}},"root":"root","version":7}
EOF
git commit -am "probe b: name matched, reference differs"
```

Expected: refused; reason contains `leak: declared type path with a path
attribute` and `leak: declared type path, locked type github`. Reset.

(c) No lock: `git rm flake.lock && git commit -m "probe c: no lock"`.
Expected: `there is none`. Reset.

(d) Outside the allow-list, honestly locked: an `hg` or `git+ssh` input
(no fetch needed for the refusal, the lock is written by hand):

```sh
cat > flake.lock <<'EOF'
{"nodes":{"g":{"locked":{"narHash":"sha256-x","rev":"0000000000000000000000000000000000000000","type":"git","url":"ssh://git@forge.example.invalid/r"},"original":{"type":"git","url":"ssh://git@forge.example.invalid/r"}},"root":{"inputs":{"g":"g"}}},"root":"root","version":7}
EOF
git commit -am "probe d: git over ssh"
```

Expected: `g: locked type git without an https url` (with the original
`flake.nix` restored, the declared side is empty, so the lock side refuses
first). Reset to the round-1 commit when done; `git log --oneline` must show
only `init` and `canary: round 1`.

## Step 5: the landing

```sh
cd "$HOME"           # outside every worktree
sc merge --target sc-canary-449/<branch> --no-post-merge --format plain
git -C "$HOME/eng/repos/sc-canary-449" fetch origin && git -C "$HOME/eng/repos/sc-canary-449" log --oneline origin/master -3
```

Expected: the guarded gate point again, the landing pushed to origin, the
round-1 commit on `origin/master`, no post-merge target run (`--no-post-merge`
is the CLI spelling of `targets=[]`). The session is closed by the merge.

## Step 6: the #455 half (optional, separate spawn)

Spawn a second confined canary as in step 2 with a brief that asks it to:
create a conflict with master (the operator first pushes a commit to
`origin/master` that changes README.md's first line), run `grit_branch
rebase upstream=origin/master`, and on the conflict call `grit_branch
rebase continue=true` and report the exact refusal. Expected: the body
refuses ("a confined caller may only touch refs and the worktree its
session owns"), because a rebase in progress owns nothing for a confined
caller. The operator finishes from outside: `git -C <worktree_path> rebase
--abort`. From an UNCONFINED dontAsk session the same continue is allowed
(the #455 fix); light-cedar can show that on a scratch branch on request.

## Done when

Steps 1, 3, 4 (a) to (d) with an empty store diff, and 5 match their
expectations. Report to the coordinator: the record points of step 3, the
four refusal lines of step 4, the landed sha of step 5, and the hard
refusals (if any) that did not match. Then `rm -rf "$HOME/eng/repos/sc-canary-449"
"$HOME/eng/repos/sc-canary-449.git" /tmp/canary-outside /tmp/canary-store-*`.
